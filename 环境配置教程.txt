在QQ上的《明日方舟》角色聊天机器人——环境配置教程
适用版本：v1.0.4

==================================================
一、需要准备什么
==================================================

1. Windows 10 或 Windows 11 电脑。
2. Python 3.11 或更高版本。
   下载地址：https://www.python.org/downloads/
   安装时务必勾选“Add python.exe to PATH”。
3. 一个用于机器人的 QQ 账号，建议使用单独的小号。
4. Docker Desktop 和 SnowLuma 协议端容器，用来让 Python 程序接收和发送 QQ 消息。
   Docker Desktop：https://www.docker.com/products/docker-desktop/
   SnowLuma 镜像：motricseven7/snowluma:latest
   请使用单独的机器人 QQ 账号；任何协议端都无法保证账号不会被平台风控。
5. 一个 OpenAI 兼容聊天接口的 API Key，例如 DeepSeek。
6. 首次运行需要联网下载 Python 依赖和约 100MB 的中文嵌入模型。
   嵌入模型下载完成后，本地记忆检索不需要 GPU。

==================================================
二、获取项目文件
==================================================

方法一：使用 Git

  git clone https://github.com/Lapt0p-1231/Arknights-QQ-Chatbot.git
  cd Arknights-QQ-Chatbot

方法二：不使用 Git

1. 打开 https://github.com/Lapt0p-1231/Arknights-QQ-Chatbot
2. 点击“Code”→“Download ZIP”。
3. 解压到一个不包含特殊权限要求的目录。
4. 后续命令都在解压后的项目根目录执行。

==================================================
三、安装 Python 依赖
==================================================

1. 在项目根目录打开 PowerShell。
   可以按住 Shift 后右键文件夹空白处，选择“在此处打开 PowerShell 窗口”。

2. 检查 Python：

   python --version

   如果提示找不到 python，请重新安装 Python 并勾选加入 PATH，
   或关闭“应用执行别名”中占用 python 命令的商店别名。

3. 创建独立虚拟环境：

   python -m venv .venv

4. 安装依赖：

   .\.venv\Scripts\python.exe -m pip install -r requirements.txt

   不需要手动激活虚拟环境，上述命令会直接使用项目内的 Python。

==================================================
四、配置模型接口
==================================================

1. 将 api.example.json 复制一份，并把副本命名为 api.json。

   PowerShell 命令：

   Copy-Item api.example.json api.json

2. 用记事本或其他编辑器打开 api.json。
3. 在 key 字段填写你的 API Key，例如：

   "key": "你的API Key"

4. 根据服务商修改 url 和 model。
   DeepSeek 示例已经预填：

   "url": "https://api.deepseek.com/chat/completions"
   "model": "deepseek-chat"

5. routes 中：
   main 是生成聊天回复的主模型。
   sub 是负责判断、总结、打分和记忆发散的副模型。
   只有一个接口时，两项保持相同即可。

也可以启动 WebUI 后，在“模型路由”页面添加端点并分配 main/sub。
api.json 含有私密密钥，不要把它发给他人或上传到公开仓库。

==================================================
五、设置机器人 QQ 和管理员 QQ
==================================================

必须通过环境变量告诉程序哪个 QQ 是机器人、哪些 QQ 是管理员。

临时方式：只在当前 PowerShell 窗口有效

  $env:QQ_BOT_QQ = "你的机器人QQ号"
  $env:QQ_BOT_ADMIN_QQ = "你的QQ号"

多个管理员用英文逗号分隔：

  $env:QQ_BOT_ADMIN_QQ = "123456789,987654321"

永久方式：保存到当前 Windows 用户

  setx QQ_BOT_QQ "你的机器人QQ号"
  setx QQ_BOT_ADMIN_QQ "你的QQ号"

使用 setx 后必须关闭并重新打开 PowerShell，或直接重新双击启动脚本。
如果 QQ_BOT_QQ 没有正确设置，机器人可能无法识别 @，也可能不能过滤自己的消息。

可选：Server酱异常告警

  setx QQ_BOT_SERVER_CHAN_KEY "你的Server酱SendKey"

不设置该变量就不会发送微信告警，不影响聊天功能。

==================================================
六、安装并配置 Docker Desktop 与 SnowLuma
==================================================

1. 安装 Docker Desktop，安装过程中按提示启用 WSL2。
   安装完成后启动 Docker Desktop，等到界面显示引擎已正常运行。

2. 在 PowerShell 检查 Docker：

   docker version

   如果提示无法连接 Docker 引擎，请先等待 Docker Desktop 完全启动。

3. 创建并启动 SnowLuma 容器。将下面整段命令复制到 PowerShell 执行：

   docker run -d --name snowluma --restart unless-stopped -p 5099:5099 -p 6081:6081 -p 3010:3000 -p 3011:3001 -v qq-client-config:/app/.config -v qq-gateway-data:/app/data -v qq-client-data:/app/.local/share motricseven7/snowluma:latest

   第一次执行需要拉取镜像，请保持网络可用。
   这条命令会创建三个 Docker 数据卷，用于保存 QQ 登录数据与 SnowLuma 配置。
   以后重启电脑只需启动 Docker Desktop，再执行：docker start snowluma

4. 打开 SnowLuma 控制台：

   http://127.0.0.1:5099

5. 按控制台提示登录机器人 QQ。
6. 在 SnowLuma 的网络配置中新建“反向 WebSocket 客户端”。
7. 地址填写：

   ws://127.0.0.1:8080

8. 保存并启用该连接。

注意连接方向：QQ-BOT.py 在 8080 端口启动服务，SnowLuma 主动连接它。
如果连接失败，先启动 QQ-BOT.py，再在 SnowLuma 控制台中重连。
建议 SnowLuma 和机器人程序运行在同一台电脑上，不要把 8080 端口暴露到公网。
SnowLuma 控制台和 QQ 登录数据也不要开放到公网；请使用独立机器人账号并注意账号安全。

==================================================
七、启动程序
==================================================

启动顺序：

1. 启动 Docker Desktop，等待引擎正常运行。
2. 执行 docker start snowluma，并在控制台登录机器人 QQ。
3. 双击项目中的“一键启动.bat”。
4. 脚本会尝试启动已有 snowluma 容器，然后启动 WebUI 和 QQ-BOT.py。
5. 浏览器打开 http://127.0.0.1:8090 可进入机器人管理页面。
6. 打开 http://127.0.0.1:5099，检查反向 WebSocket 是否显示已连接。

也可以手动启动：

第一个 PowerShell 窗口：

  .\.venv\Scripts\python.exe part_web.py

第二个 PowerShell 窗口：

  .\.venv\Scripts\python.exe QQ-BOT.py

WebUI 默认仅监听 127.0.0.1，且没有登录认证。
不要将 QQ_BOT_WEB_HOST 改成 0.0.0.0 或公网地址，除非你已经自行增加访问控制。

==================================================
八、启用白金人设
==================================================

标准版中的白金人设默认关闭。

1. 打开 WebUI。
2. 进入提示词管理页面。
3. 找到“02_角色人设（白金）.txt”并启用。
4. 修改后立即生效，不需要重启机器人。

也可以用私聊指令“/char set <角色设定>”给单个用户设置专属人格。
发送“/cmd help”可以查看当前场景和权限下可用的指令。

==================================================
九、首次运行会生成什么
==================================================

以下文件只保存在你自己的电脑上，不属于公开标准版：

  data/                 聊天记录、用户档案、SQLite 和 ChromaDB 数据
  models/               本地嵌入模型缓存
  user_log/             旧版档案迁移目录
  api.json              模型接口和密钥
  bot_settings.json     个人运行参数
  prompts_config.json   提示词开关配置
  QQ-BOT.log            运行日志

这些文件已经写入 .gitignore。不要强行提交或公开分享。

==================================================
十、常见问题排查
==================================================

1. 机器人完全不理我
   - 确认 QQ_BOT_QQ 是机器人自己的 QQ，不是你的 QQ。
   - 确认 SnowLuma 反向 WebSocket 已连接 ws://127.0.0.1:8080。
   - 默认群聊主要响应 @机器人，可先尝试 @机器人 发言。
   - 查看 QQ-BOT.py 窗口和 QQ-BOT.log 中的报错。

2. 提示 401 / Unauthorized
   - api.json 中的 key 错误、失效或没有填写。
   - 确认 key 属于当前 url 对应的服务商。

3. 提示模型不存在或 404
   - 检查 model 名称和 url 是否与服务商文档一致。
   - 不要把其他服务商的模型名直接用于 DeepSeek 官方地址。

4. SnowLuma 一直连不上
   - 确认 Docker Desktop 已正常运行，并执行 docker ps 检查 snowluma 容器。
   - 确认已先运行 QQ-BOT.py。
   - 检查是否选成“反向 WebSocket 客户端”，地址是否为 8080。
   - 检查 8080 是否被其他程序占用：

     netstat -ano | findstr :8080

5. 第一次启动卡在向量模型加载
   - 首次运行需要下载嵌入模型，请保持网络可用并耐心等待。
   - 模型位于本地 models/ 缓存中，下载成功后无需重复下载。

6. 修改设置后没有生效
   - 模型路由、提示词和多数 WebUI 设置会实时生效。
   - 环境变量修改后需要重启 QQ-BOT.py。
   - 使用 setx 后需要重新打开终端或启动脚本。

完成以上步骤后，即可在私聊中 @或直接发送消息测试，在群聊中优先使用 @机器人 测试。
